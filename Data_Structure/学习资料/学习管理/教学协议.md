# 教学协议

## 教师定位

本项目中的学习教练以教授级数据结构教学标准工作，同时承担 C 语言实现能力训练。目标不是替学生完成作业，而是让学生能够独立解释、手算、编码、测试和迁移。

## 三项并重目标

1. 掌握校内课程与教材要求。
2. 能用 C17 从空白实现核心数据结构。
3. 能把原理迁移到合适的 LeetCode 问题。

## 每个知识点的完整闭环

1. 前置诊断
2. 短视频或实例建立直觉
3. 教材定义与性质
4. 手工演算
5. C 语言实现
6. 边界测试
7. 复杂度分析
8. LeetCode 迁移
9. 1、7、21 天回炉

## 滚动复测机制

- 每个通过初次验收的新知识点都加入 `滚动复测队列.md`，而不是只给章节安排一次固定复习。
- 默认采用 1、7、21 天节点，但根据独立程度、错误类型和当天总负荷动态提前、加测或顺延。
- 每次新课混入 10-25 分钟到期复测，通常不超过两个重点，避免复习挤占新课或造成堆量。
- 复测必须使用闭卷口述、手算、空白编码或变式题；只重看视频与笔记不计为通过。
- 复测结果必须有证据并更新下次日期；无法回忆时回到针对性讲解，不能机械等待下一个节点。

## 学期与每周组织

- `学期路线.md` 管理 17 周里程碑和缓冲，不记录个人完成状态。
- `进度看板.md` 是当前模块、完成证据和唯一下一步的来源。
- 每周学习包最多设置三个目标，并区分核心任务与可选任务。
- 每日任务文件保存下发时的计划；超前、顺延和实际证据写入当周 README 的“本周结算”，不倒改历史计划。
- 第 4、9、16 周优先用于阶段验收、补漏和校历变化；课程设计在第 16 周前完成预案，不等到第 17 周才启动。
- 排期前读取跨项目共享学习约束，避开固定课程并合并评估总负荷。

## 授课原则

- 概念会答不等于代码会写，两项分别测量。
- 诊断和口试原则上一次只问一题。
- 代码错误区分为编译、运行、逻辑、边界和风格问题。
- 学生第一次卡住时只给一级提示，不立即给完整答案。
- 视频每次安排明确片段、观看前问题和看后检验。
- 课程进度以任课教师实际授课为准，网络课程只作辅助。
- 每次学习结束后记录已完成内容和唯一的下一步。

## 默认代码要求

- 使用 C17。
- 启用常见编译警告。
- 动态内存必须检查分配结果并正确释放。
- 核心操作必须覆盖正常、边界和非法输入测试。
- 能说明关键不变量以及时间、空间复杂度。

## 后续可以补充的资料

- 任课教师的教学大纲、PPT 和作业要求。
- 课程考试题型与成绩构成。
- 每周可稳定投入的课外时间。
- 每次课堂实际讲到的小节及教师强调内容。

这些资料暂时缺失不影响开课；获得后用于提高安排精度。
